# 疲劳机多源监测数据分析系统

本工作区用于疲劳机多源监测数据（试件 001-027）的**离线对齐**与**在线结构健康监测（SHM）**。
每个试件文件夹包含同一疲劳实验流程的三种传感器数据：光纤、声发射（AE）、应变（均 10Hz）。
系统提供离线批量对齐、在线逐点流式处理、以及在线/离线对比三种工作流。

---

## 1. 项目简介

针对疲劳试验中光纤、声发射、应变三种传感器各自独立采集（采样率 10Hz、时间戳格式不统一、存在丢数据）的问题，本系统：

- **统一时间轴**：自动识别并统一换算各源时间戳为秒（10Hz）
- **离线对齐**：以 AE 事件为网格，将光纤/应变对齐到每个 AE 事件时刻，完整保留 AE 原始事件
- **在线监测**：逐点流式处理，实时输出结构损伤阶段（健康→微损伤→扩展→失效）与异常预警
- **在线/离线对比**：同一数据分别走在线（因果、逐点）与离线（全局、批处理）两条路径，对比阶段划分一致性、计算效率与延迟

## 2. 数据说明

每个试件目录（`001`~`027`）包含三种传感器文件（`.csv` 或 `.xlsx`）：

| 文件               | 内容                                                  | 时间戳格式                         |
| ------------------ | ----------------------------------------------------- | ---------------------------------- |
| `*光纤.csv/xlsx` | 多通道应变（列名`s1..sN` 或 `strain/strain1`）    | `Time Stamp` 0.1s 计数，需 ×0.1 |
| `*声发射.csv`    | AE 事件特征（25 列：Mean/RMS/Peak/Kurtosis/谱能量…） | **无时间戳**，事件序列       |
| `*应变.csv/xlsx` | 应变幅值                                              | 秒（dt=0.1）或 0.1s 计数（dt=1.0） |

**采样率与时间轴**：所有数据均为 10Hz。光纤 Time Stamp 相邻差≈1.0 为 0.1s 计数单位（×0.1 得秒）；应变有两种（dt≈0.1 已是秒 / dt≈1.0 需 ×0.1）。系统按中位间隔自动判断。

**数据概况（代表性组）**：

| 组号 | 数据量级 | 关键特征                                                                               |
| ---- | -------- | -------------------------------------------------------------------------------------- |
| 016  | ~50k     | 应变均值 7.6，末段跳升至 21.7；AE 有 474 个 Kurt>100 事件；光纤 5 通道平稳             |
| 017  | ~46k     | 应变循环加载，末段跳升至 60.9；AE 有 989 个 Kurt>100 事件；光纤 s4 通道剧烈交替振荡    |
| 018  | ~35k     | 应变均值 18.4，末段升至 28.2；光纤仅 1 通道                                            |
| 019  | ~40k     | **关键故障组**：应变在 t≈106s 从 0.1 跳变至 8.4，AE 出现 Kurtosis>1000 极端事件 |
| 020  | ~59k     | 应变均值 36.5；光纤 5 通道大幅波动（-71~+47）                                          |
| 其他 | ~30k-60k | 部分组缺少光纤或应变数据                                                               |

> **注意**：`001-005`、`015` 六组可能存在数据问题（缺失源、通道空白等），在线/离线对比与分析时通常排除，使用有效组 `006-014, 016-027`。并非所有组都有三类完整数据，系统自动检测可用源，缺失源自动跳过。

## 4. 架构总览

系统围绕"统一时间轴"与"多源融合"设计，三种工作流共用同一数据加载与时间同步基础：

```
原始数据(光纤/AE/应变) ──► 统一10Hz时间轴
        │
        ├──► 离线对齐(align.py)   : AE网格，保留AE全部事件 → aligned\{sid}.csv
        │
        ├──► 在线监测(online.py)  : 逐点流式 → 阶段划分 + 异常预警 + 实时仪表盘
        │
        └──► 在线离线对比(compare.py): 同数据两条路径 → 一致性/效率/延迟
```

**两种对齐策略（按用途刻意分离）**：

| 方案     | 入口                                    | 策略                                                                                                                                                                            |
| -------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 离线对齐 | `align.py`                            | 以**AE 事件为网格**：AE 行号均匀映射到实验时长 `[0,T]`，光纤/应变线性插值到每个 AE 事件时刻（仅有效覆盖范围）。输出行数 = AE 事件数，AE 原始特征 100% 保留。            |
| 在线对齐 | `shm\data_loader.py::sync_timeline()` | **松散对齐**：以应变时间戳为统一主时钟（头尾对齐），光纤精确匹配（保留原始点），AE 事件仅在事件位置填值；流式读取时对无新数据的位置**保持上值**（不插值、不填空）。 |

## 5. 离线对齐（AE 网格）

`align.py` 对试件 `006-027` 批量执行：

1. **统一时间换算**：`ts_to_seconds()` 按中位间隔自动识别 0.1s 计数并 ×0.1
2. **数据清洗**：跳过 `015` 文件头、剔除全空通道、处理 NaN
3. **确定实验时长**：以应变为主时间基准（无应变时用光纤），自动检测各源覆盖与丢数据段（`detect_gaps`）
4. **AE 网格对齐**：AE 事件行号均匀映射到 `[0,T]`，光纤/应变线性插值到每个 AE 事件时刻（仅有效覆盖范围，不外推伪造）
5. **输出**：`aligned\{sid}.csv`（行数 = AE 事件数，含 `ae_event/ae_time_s/ae_norm` + 全部 AE 原始特征 `ae_*` + 光纤 `fiber_*`/`fiber_mean` + `strain`）+ `对齐元信息.csv`（时长、缺失段、覆盖、问题）

```
AE事件:     ●────●──●──────●───●─────●        （行号 → [0,T]）
光纤(10Hz): ●─●─●─●─●─●─●─●─●─●─●─●─●─●      （插值到每个AE事件时刻）
应变(10Hz): ●─●─●─●─●─●─●─●─●─●─●─●─●─●
```

## 6. 在线结构健康监测

### 6.1 数据加载与松散对齐

`DataLoader` 统一加载三类数据，`sync_timeline()` 生成松散对齐时间轴：

- 主时钟 = 应变时间戳网格（无应变时用光纤），所有源共享时间头尾
- 光纤按精确时间戳匹配（同为 10Hz 网格，`round(3)` 消除浮点误差），无匹配置 NaN
- AE 事件均匀映射到主网格，**仅在事件位置填值**，其余为 NaN
- 兼容光纤列名（`s1..sN` 与 `strain/strain1` 统一映射）

`ChunkedDataReader` 将对齐结果转为**内存 numpy 数组**逐行迭代（无临时文件 I/O），流式读取时对 NaN 位置**保持上值**（`get_row_dict`，事件流更新语义）。

### 6.2 在线归一化与特征提取

- `OnlineNormalizer`：滑动窗口归一化（应变 min-max、AE log1p+min-max、FO Z-score），仅用历史窗口，不窥探未来
- `OnlineFeatureExtractor`：逐点提取应变（均值/差分/累积）、AE（峰值/峰度/RMS/谱能量/异常分数/事件率/累积能量）、FO（均值/极差/Z-score）特征

### 6.3 在线阶段划分状态机

阶段单调递增（0→1→2→3），不可逆：

```
  ┌──────────┐   应变跳变/AE能量激增    ┌──────────┐
  │ Phase 0  │ ───────────────────────► │ Phase 1  │
  │  健康期   │     FO显著偏移           │ 微损伤期  │
  └──────────┘                          └──────────┘
       ▲                                       │
       │                                       │ 应变大幅跳变
       │                                       ▼
       │                                  ┌──────────┐
       │                                  │ Phase 2  │
       │  FO/应变综合判断                  │ 扩展期    │
       │                                  └──────────┘
       │                                       │
       │                                       │ 持续高置信(窗口确认)
       │                                       ▼
       │                                  ┌──────────┐
       │                                  │ Phase 3  │
       │                                  │ 失效期    │
       └──────────────────────────────────└──────────┘
```

每个点分别计算**应变跳变 / AE 跃迁 / FO 漂移 / 连续异常**四种置信度，注意力机制加权融合为融合分数，超过该阶段自适应阈值且满足最小阶段时长即跃迁。

- **自适应阈值**：启动后收集基线（500 点），基于噪声水平动态计算各阶段阈值、冷却周期
- **Phase 3 确认**：进入失效期需"最近 `PHASE3_CONFIRM_POINTS`(100) 点中 ≥50% 融合超阈值"，防止早期尖峰导致失效期过早/过长
- **连续异常**：`OnlineAnomalyDetector` 的融合异常作为第 4 信号；连续异常 ≥`ANOMALY_TRANSITION_MIN`(100) 点开始贡献置信度，≥`ANOMALY_TRANSITION_FULL`(300) 点满置信度

### 6.4 在线异常检测

`OnlineAnomalyDetector` 分别对三源做异常判定（应变滑动窗口 Z-score、AE 异常分数/峰度、FO 极差/通道 Z-score），再按当前阶段权重融合为综合异常布尔值，并参与阶段跃迁。

### 6.5 阶段实时指示器与异常预警

`StreamProcessor` 每次输出除阶段外，额外提供实时指示与预警字段（供 `compare.py --mode online` 与仪表盘使用）：

| 字段             | 含义                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------- |
| `phase_name`   | 当前阶段名（健康期/微损伤期/扩展期/失效期）                                           |
| `phase_points` | 当前阶段已停留点数                                                                    |
| `anomaly_run`  | 连续异常点数                                                                          |
| `anomaly_rate` | 最近 100 点异常率                                                                     |
| `alert_level`  | 预警级别**0正常 / 1注意 / 2警告 / 3严重**（连续异常≥300 或异常率≥0.3 为严重） |

### 6.6 实时仪表盘

`RealtimeDashboard`（Flask + SSE + Chart.js）逐点推送结果，前端展示当前阶段、处理进度、**预警状态**（颜色+闪烁）、连续异常、异常率、应变/AE/FO 实时曲线、阶段分布柱状图与运行日志，预警升级时写入日志。

### 6.7 在线性能

在线逐点处理为纯 Python 流式，已做无损优化（结果与未优化完全一致）：

- `OnlineBuffer`：环形数组 + 增量 `sum/sumsq/count`，`push`/`get_mean_std` 为 O(1)
- 特征峰度/偏度用 numpy 手算（替代 pandas `Series.kurtosis/skew`）
- `ChunkedDataReader` 内存 numpy 迭代（消除临时 CSV I/O）

以 016（50118 点）为例：完整处理约 27~37s（每点 ~0.6~0.7ms）。

## 7. 在线离线对比

`compare.py` 对同一数据分别走在线（因果、逐点）与离线（全局、批处理）两条路径，支持三种模式：

```bash
python compare.py --mode online  --groups 016 018   # 纯在线（含实时指示器/预警）
python compare.py --mode offline --groups 016 018   # 纯离线（批处理基准）
python compare.py --mode compare --groups 016 018   # 在线离线同步比较（默认）
python compare.py --mode compare --all              # 全部有效组(006-014,016-027)
```

**离线基准**（`shm\batch_divider.py`）：`BatchStageDivider` 用应变 CUSUM 二分分割找 3 个水平变点 → 4 阶段（全局、一次性）。

**对比指标**（无真实断裂标签，故比较一致性而非绝对准确率）：

| 指标       | 含义                                                        |
| ---------- | ----------------------------------------------------------- |
| 阶段一致性 | 在线与离线基准逐点阶段匹配率                                |
| 计算效率   | 在线逐点耗时 vs 离线批处理耗时                              |
| 跃迁延迟   | 在线各阶段跃迁点 vs 离线基准跃迁点的位置差（正 = 在线偏早） |

实测（016/018）：离线比在线快约 1-2 万倍（向量化 vs 逐点 Python）；一致性因组而异（016 约 87%、018 约 6%，在线对 AE 尖峰敏感的组阶段推进偏快）。

## 8. 关键参数配置

集中管理于 `shm\config.py`，按需调整：

| 参数                            | 默认      | 含义                                      |
| ------------------------------- | --------- | ----------------------------------------- |
| `BASELINE_LENGTH`             | 500       | 自适应阈值基线收集长度                    |
| `MIN_STABLE_POINTS`           | 500       | 前 N 点不允许任何阶段跃迁                 |
| `MIN_PHASE_DURATION`          | 300       | 每个阶段最少持续点数                      |
| `COOLDOWN_DEFAULT`            | 500       | 默认跃迁冷却周期                          |
| `ANOMALY_TRANSITION_MIN/FULL` | 100 / 300 | 连续异常开始/满置信度点数                 |
| `PHASE3_CONFIRM_POINTS`       | 100       | Phase3 确认窗口（最近 N 点 ≥50% 超阈值） |
| `NORMALIZER_WARMUP/WINDOW`    | 100 / 200 | 归一化预热与窗口                          |
| `CHUNK_SIZE`                  | 1000      | 分块大小（现为内存迭代，保留兼容）        |

## 9. 使用方式

```bash
# ① 离线批量对齐（006-027）→ aligned\
python align.py

# ② 在线实时仪表盘（默认 016）
python online.py dashboard --group 016 --speed 10 --port 5000

# ③ 在线批量处理（无界面）
python online.py batch --groups 016 017 018 019 020 --speed 10

# ④ 在线流式快速测试
python test.py --group 016 --max-points 1500

# ⑤ 在线/离线对比（三种模式）
python compare.py --mode online  --groups 016 018
python compare.py --mode offline --groups 016 018
python compare.py --mode compare --groups 016 018
python compare.py --mode compare --all
```
