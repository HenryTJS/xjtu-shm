### 1.2 数据集 A：主样本 016-020

- **采样**：光纤/应变 10 Hz 连续；AE 为事件/窗口特征（每 0.1 s 窗口整合 25 项指标）。
- **对齐**：`main/prepare_data.py align` 以 AE 事件为网格、应变时间为主基准；逐点流式读取，AE 事件门控（仅新事件计入能量）。
- **块**：`EXT_BLOCK_PTS=500`（≈50 s）。
- **工况**：5 Hz 正弦载荷控制；016-019 峰值 10 / 谷值 1.0 kN，**020 为 8 / 0.8 kN**（故严格同工况只有 4 组）。
- **硬限制**（详见 §5）：
  - AE **无到达时间**（事件时间由 `np.linspace` 均匀生成）→ **事件速率类指标不可用**；
  - AE **单通道** → **无法 TDOA 定位**；
  - **解调口径不统一**：26 个通道中仅 016 应变已解调（`alt=0.94`），其余 25 个（含全部光纤）`alt=4.9~352`。

### 1.3 数据集 B：L1 第一批（4 组）

**试件与材料**（来源：`l1/broer-et-al-2021-*.pdf`，2026-09-15 核对）

- **单 T 筋加筋板**（co-cured 蒙皮 + 单根 T-stiffener）
- **材料 = IM7/8552 碳纤维-环氧单向预浸料**（有公开数据手册值；**登记在此仅作材料背景**）
- **铺层**：蒙皮 `[45/−45/0/−45/90/−45/0]`、筋条 `[45/−45/0/−45/−45]`
  ⚠️ PDF 是双栏版式，文本提取会串行 → **引用前须核对原文 Figure 2**
- **冲击 10 J** → BVID；随后 −6.5/−65 kN、2 Hz 压-压疲劳
- **板尺寸 165(X) × 243(Y) mm**；4 只 AE 传感器，skin 面、左下角起算：
  **S1(145,190) S2(145,20) S3(20,50) S4(20,220)** —— **13 组完全一致**
- **各组 PDF 另给出双向实测声速**（横向 $v_x$、纵向 $v_y$），见 §2.4 与 `l1/ae_locate.py` 的 `VEL`
- **FBG 块锚**：每约 5000 cycle 停机测一段（块数 = L1-03: 30 / L1-04: 56 / L1-05: 29 / L1-09: 28）→ **块 k ↔ cycle ≈ k×5000**，这是本项目**唯一可靠的 cycle 锚**。
- **DFOS**：与 FBG 同墙钟，每块内约 14 行快照（两加强筋脚）。
- **AE**：事件级（Vallen hit 列表）；四组覆盖 **99.1~99.9%**（L1-04 = 99.9%）。
  ⚠️ L1-04 的 `.pridb` 由**时间基互相独立**的两段构成（两段都从 ~0 起算、事件零重叠），
  必须先按会话**缝合**再排序；旧代码直接按 `Time` 排序会把两段交错，使其 AE 看起来
  只覆盖 61.3% 寿命（已定位为时间基断裂伪影并修复，读入统一走 `l1/ae_io.py`）。
- **元信息自动解析**：`l1/l1_meta.py` 从各组 `L1-xx.pdf` 解析 n_f / 左右脚空间段，**不硬编码**。

### 1.4 数据集 C：L1 第二批（9 组）

- **无 FBG**（PDF 的 FBG 栏为 No），只有 AE(`.pridb`) + ODiSi-B DFOS。

导致定位的"准确性"**永久不可评估**（§5.7）。为补上这一块，引入

| --- | --- |

| ✅ **定量真值**（光学实测**裂纹长度 mm**） | ❌ 试件仅 **8** 个 |
| ✅ **精确循环锚** + 训练/验证划分 | ❌ 只给单对传感器 ⇒ **无定位能力** |

> ⚠️ **它不改变 A/B/C 的任何结论**（物理不同），也**不填补 ReMAP 的 NDT 真值缺口**。
> 它的唯一用途是回答「**这个损伤指标对不对**」——这是本项目一直无法回答的问题。

**已跑通的四步与结果**（2026-09-20 ~ 09-21；路径：Step 0 规整 → Step 1 特征/基线 →
Step 2 波形级 DL → T7–T8 外推评测。原计划的「接入 `run.py`」未做，其目的已被外推评测承担）

| 步 | 做什么 | 结果 |
| --- | --- | --- |
| **Step 0** | 数据规整 + **8 项核对** | `time` 列 **92/94 不可用**（被 Excel 量化成科学计数法）⇒ 重建 `t[i]=i×5×10⁻⁸ s`；带通 100~300 kHz 把重复性 corr **0.9545 → 0.9985**、relRMS 差 33.5% → 5.6%；**噪声下界 = 6%**（此后成为"是否真检出损伤"的硬标尺）。核对还**撤销**了"T5 不可用"的误判 |
| **Step 1** | 32 特征 + LOSO 8 折 + 10 个对照臂 | 最优 `linear+单调约束` RMSE **1.501 mm** / MAE 1.233 / 折内 rho 0.928；`rf+约束` 折内 rho **0.970**（量程 0~7.46 mm）。**TOF 被证否**（折内 rho ≈ 0，因为裂纹改的是透射幅值/波场形状，不是直达波路径长度） |
| **Step 2** | 波形级 DL（1D/STFT × 1/2 通道 × 2 种参考口径） | 最优「2 通道 CNN + 约束」RMSE **1.692 mm** / MAE 1.410 / 折内 rho **0.934** / 零裂纹误报 **24%**。**DL 没有击败特征工程（1.692 vs 1.501），但健康端误报最低（24% vs 38~50%）** |
| **外推/预后** | T7/T8 的波形只给前半段，真值给到后半段 | **T7（等幅→等幅）** `lin_last2`/`lin_all` RMSE **0.668 / 0.830 mm**，可用；**T8 视界 23843 循环 > 截断自检极限 13133（1.8×）⇒ 精度不可验证**，只能作方法演示 |

**三条可复用的方法学结论**（这是引入该平台的**主要产出**）：

1. **对比 DL 与特征工程必须保证信息对等**。Step 1 最强的特征需要"看到健康基线"，
   而单通道 CNN 只看一个波形 ⇒ 补上"相对参考波形的差值"通道后
   RMSE **2.084 → 1.692**、零裂纹误报 **88% → 24%**。否则"DL 更差"只反映输入设计缺陷。
2. **增长律选型必须按视界分层**。短视界（几千循环）选出的 Paris 律在 T8 的长视界上
   **爆炸（RMSE 476 mm）** —— 因为 $p>1$ 有有限时间奇点，短视界看不出来。
   这是**负面结论**，同样要报。
3. **物理约束层（保序投影 + 非负）在 4 个特征工程臂 + 10 个 DL 配置上全部有效**，
   且**降低** RMSE（而非通常的"牺牲精度换可解释性"）—— 因为本数据的裂纹确实单调增长，
   约束剔掉的是模型抖动。投影只用"按循环数排序"，**不用标签**，不构成泄漏。

同时保留两项**负面/加固结论**：

- **等损伤当量换算无效**。T1–T7 的载荷剖面**完全相同**（等幅 95.44 kN），T8 是两级块谱
  （500 循环 85.23 + 500 循环 95.44），幅值只差 **5.3%** ⇒ 当量系数 0.80~0.94；
  换算后 T8 视界 23843 → 19475~21413，**仍是自检极限的 1.48~1.70 倍**。
  又因全部候选增长律对循环轴均匀缩放**等变**，实测预测变化 ≤**0.037 mm**（0.5% 量程）、
  发散数**一格未变** ⇒ 该动作被排除，T8 的失败与载荷谱无关。
- **健康原点锚定（`--anchor`）不能降低零裂纹误报**（24% 一格未动），
  但能把无约束 CNN 的 RMSE 降 9.1%（1.857 → 1.688），且**成本为零**（后处理、不用标签）。
  ⇒ 反证误报是**数据侧漂移**问题（健康期波形本身在变），与 Step 1 的零裂纹归因独立同源。

**诚实边界**：① 精度瓶颈是**跨试件绝对标定**（折内 rho 0.93~0.97 但 RMSE 1.5~1.7 mm，
预测值域被压缩到 0.5~0.75 倍）；② 零裂纹误报 24~50% 的主因在数据，
且 **T1/T2/T4/T6 各只有 1 个零裂纹时刻 ⇒ 基线稳定性无法自检**；
③ 每试件只有 3~5 个测量点 ⇒ 增长律参数欠定；④ 官方评分函数未实现
（常数文件不在副本内），只用 RMSE/MAE 这类无歧义口径；⑤ 8 个试件做 LOSO
= 必须外推到完全没见过的工况。完整解读与全部数值不在此展开。
另注：实测全部 15 个 L1 `.pridb` 的 `acq_setup` 为 `<TR Enabled="False">`
⇒ **ReMAP 的 AE 波形从未被记录**（不是"没交付"），这是引入外部平台的直接原因。

## 2. 方法

### 2.1 统一框架：连续损伤度 D(t)

目标：由多源信号**在线**算出 $D(t)\in[0,1]$ —— **逐点流式、零未来信息、不使用标签**。

**源架构**：声发射为**主源**（每组必做单源基线）；应变、光纤为**辅助源**，按数据有无参与二源/三源融合。

**证据层**（`shm/damage_index.py`）：

| 证据                          | 含义                                                                   | 权重上限 |
| ----------------------------- | ---------------------------------------------------------------------- | -------- |
| `e_dmg`                     | AE「损伤型事件」能量（logE 超滚动背景分位 + 抬升量）→ 块能量 log EWMA | 主源     |
| `e_full`                    | AE 全能量累积 log 加速度（短/长窗斜率差 EWMA）                         | 主源     |
| `e_shape`                   | AE **形状/比值列**（`Kurtosis` 等）块内 p95 相对固定校准段基线的抬升（可选，**默认关**，见 §3.6） | ≤0.60   |
| `e_ae = max(e_dmg, e_full[, e_shape])` | **主源**（5 组全达 1.00）                                        | 1.00     |
| `e_strain`                  | 应变块 std 相对运行中位发散                                            | ≤0.60   |
| `e_fo`                      | 光纤多通道**去共模空间极差**相对运行中位发散（通道 ≤1 时 ≡0）  | ≤0.60   |

**状态层**：`risk = <融合算子>(启用源证据)` → D **升快降慢**累积 → 分级。默认 `sources=('ae','strain')`、`fusion='max'`。

**latch（损伤确认后加速追赶，默认开）**：当 D 经**不可逆确认**（最近 3 块 `min≥0.15 且 ≥0.30`）后，对 risk 用快 rise 追赶，保证 0.85 级可达，且**不改变预警 onset**（5 组验证）。

**评估口径**：A-预警 = D 首次「不可逆」≥0.3（2% 寿命窗内不回落到 0.15）。

### 2.2 三级预警语义（0.25 / 0.55 / 0.85）

三级不是同一条曲线的三个高度，而是**三种不同性质的判断**：

| 级别 | 阈值           | 语义                                   | 触发机制                                         |
| ---- | -------------- | -------------------------------------- | ------------------------------------------------ |
| 注意 | $D \ge 0.25$ | 检测到损伤**起始**               | AE 证据首次抬升                                  |
| 预警 | $D \ge 0.55$ | 损伤**不可逆确认**（非"更严重"） | latch 确认后 D 追上 risk；016 另需刚度损失 ≥10% |
| 临危 | $D \ge 0.85$ | **已无剩余裕度**                 | D 接近饱和；016 另需刚度损失 ≥50%               |

实测触发（主样本，块 = 500 点 ≈ 50 s）：

| gid | 注意  | 预警  | 临危  | 临危距断裂 |
| --- | ----- | ----- | ----- | ---------- |
| 016 | 45.9% | 46.9% | 95.8% | 3.2%       |
| 017 | 84.8% | 85.9% | 87.0% | 12.0%      |
| 018 | 71.0% | 72.4% | 73.8% | 25.2%      |
| 019 | 78.8% | 80.0% | 81.3% | 17.7%      |
| 020 | 73.0% | 73.9% | 74.7% | 24.3%      |

**注意与预警必然相邻**：latch 门槛（0.30）紧邻 0.25，确认后 rise 由 0.12→0.5，一个块内 D 即可从 ~0.29 追到 ~0.69（016 块 46→47：0.288→0.687）。这是**"损伤一旦可检出即已进入快速退化段"的物理反映**，不是标定缺陷。

> 「分级设计」的硬约束与已被证否的扩展路线：不在此展开。

### 2.3 各数据集的适配

| 环节               | **A 主样本**    | **B L1 第一批**                                       | **C L1 第二批**                   |
| ------------------ | --------------------- | ----------------------------------------------------------- | --------------------------------------- |
| 点网格 / 块        | 10 Hz 逐点，500 点/块 | **1 点 / 10 cycle** → 500 点 = 5000 cycle = 1 FBG 块 | 段级数据重采样到**10-cycle 网格** |
| 应变来源           | 应变传感器（连续）    | FBG 块均值                                                  | ODiSi-B DFOS 脚部段（中位分布）         |
| 基线               | 直接起算（有健康期）  | **基线重定义**：c0 = 冲击后稳定态终点                 | 冲击后前 10 段                          |
| 关键参数           | `rise=0.12`         | `rise=0.05`                                               | 同 B                                    |
| 失效锚             | b3                    | n_f                                                         | n_f                                     |
| **时间对齐** | 10 Hz 统一轴（可靠）  | FBG 块锚（可靠）                                            | ⚠️**无锚** → 按寿命均匀近似    |

**为什么需要适配**：主样本有"健康基线 → 检测起始"；L1 是**冲击后疲劳**（0 cycle 即 BVID），早期冲击脱粘 AE 会被判为"损伤型事件" → 默认参数下 D 在 ~20% 寿命即饱和。**基线重定义 + 应变漂移证据**即为此设计（均自动、无硬编码）。

### 2.4 扩展任务方法（数据集 C）

数据集 C 无 FBG，故主线的"cycle 锚 + 分级"不可直接用。改做三项**不依赖绝对寿命**的任务：

| 任务                      | 方法                                                                                                                                     | 关键前提                                   |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |

### 3.8 基线对照（论文必备：**证明"比现有方法好"**）

「我们的方法能用」≠「比现有方法好」。`main/evaluate_baselines.py` 给出**同口径、同预警判据、同指标**的对照。

**方法学设计**（为避免"稻草人基线"指责）：

1. **阈值 oracle 扫描**：阈值型基线在网格上扫一遍，报**事后最优阈值**下的最佳结果；
2. **消除跨试件尺度差**：所有指标按各组**自身校准段**（块 [20,45)，与 `stiff_cal`/`shape_cal` 同窗口）归一 → 跨试件阈值才有意义；
3. **统一预警判据**：块级「首次不可逆越阈」（`h ≥ level` 且其后 `hold` 块内不回落至 `level×0.5` 以下），`hold = max(4, 2% 块数)`，与本项目逐点规则同构；
4. 基线给足条件：累积量、EWMA、ML 都用同一块网格与同一判据。

括号内为 `lead = f_est − t_warn`（百分点，正 = 报警早于物理锚）。

**表 3 的结论**

1. ✅ **本项目（AE 单源）是唯一在 12/12 组都"有报警且不属过早"的方法**（lead −0.4 ~ +58），零漏报。
2. ✅ **基线在 12 组上普遍崩坏**：B1 对 **026 漏报**；B4（监督 ML）对 **017/021/022 漏报**、
   对 019/020 提前 97 个百分点；B3 对 019 提前 97 个百分点。**只有 B2 在 024 上打平（71.0 vs 72.1）**。
3. 🔴 **多源交付口径在 023/024/025 上全部"过早"（+71/+69/+78），AE 单源全部"合理"** ——
   与 §3.8 结论 3 同源（RAW 应变通道块 std 漂移 → `e_strain` 提前越阈）。**单源在此是必要条件，不是偏好。**
4. ⚠️ **`f_est` 的适用边界**：对 **021 不可靠**（其 `f_est = 33.2%` 更像早期局部事件而非断裂 ——
   这正是不把它纳入交付的原因）。**021 是全表唯一"所有方法都过早"的组**（B1 +23 / B3 +16 / 本项目 +28），
   它在物理上就没有可用的锚，故列为**问题组**。
5. ⚠️ **零提前量案例**：026（lead −0.4）、022（+2）—— 报警与物理事件同期。按已确认口径**接受**，
   但工程上应注明"此类报警不含提前量"。

### 3.9 留一试件交叉验证（LOSO）：**5/5 不是靠调参调出来的**

**问题**：`b2` 锚与全部参数（`rise/fall/acc_scale/lift/shape_w/shape_q/latch_*`）都在**同一批 5 组**上定的。
审稿人必然问「换一组试件，参数还成立吗？」→ `main/evaluate_loso.py`

**设计**：候选网格 = 默认 + **一次一变**的 18 个变体（5 个既有参数 ±30% + `shape_w`/`shape_gain`/`shape_q`/`latch_rise_fast` 各两档）= **19 个配置**；
每个**留出一折**：在其余 4 组上选**单个最优配置**，再用它评估留出的那一组（该组标签从未参与选择）。

**结果（`results/loso_summary.csv`）**

| 设定 | 级 A | 漏报 C | 均值±\|err\| | 均值 lead | 配置 |
| --- | --- | --- | --- | --- | --- |
| **LOSO（留一选参）** | **5/5** | 0 | **1.63** | — | **1 种 / 5 折** |
| default（样本内，= 论文主结果） | 5/5 | 0 | 2.05 | 28.3 | `default` |
| oracle（事后最优） | 5/5 | 0 | 1.63 | 28.7 | `rise=0.156` |
| **网格内最差配置** | **5/5** | 0 | 3.17 | 27.2 | `rise=0.084` |

**三条结论**

1. ✅ **LOSO 与 oracle 完全一致（\|err\| 1.63），且优于默认口径（2.05）**，5/5 级 A 保持不变
   ⇒ **主结果不是在同一批试件上调参调出来的**。逐折明细（`results/loso_cv.csv`）：
   5 折全部选中 `rise=0.156`，留出 \|err\| = 2.09 / 2.28 / 1.29 / 0.52 / 1.96。
2. ✅ **网格内最差配置仍为 5/5 级 A**（\|err\| 3.17）⇒ 在 ±30% 参数区间内**结论对参数极不敏感**。
3. 敏感/惰性参数（\|err\| 对比）：

   | 参数 | 敏感 | 惰性（±30% 对结果**零影响**） |
   | --- | --- | --- |
   | 证据 | `rise`(0.084→3.17 / 0.156→1.63)、`shape_q`(**50→3.00** vs 95→2.05)、`shape_w`(0.3→2.75 / 0.6→**2.05** / 1.0→2.34)、`acc_scale`(0.026→2.58) | `fall`、`estrain_w`、`shape_gain`、`latch_rise_fast`、`lift`、`acc_scale=0.014` |

   - `shape_q=50` 明显劣于 95 ⇒ **块内高分位是必要的**，与 §3.6「025 的信号是突发事件型」**互相印证**；
   - `shape_w=0.6` 是该网格内最优（0.3 → 2.75，1.0 → 2.34）⇒ 取 0.6 的选择**在 LOSO 下依然成立**；
   - `fall`/`estrain_w`/`shape_gain`/`latch_rise_fast`/`lift` 完全不敏感 ⇒ 它们**不是"特调"出来的**。

**必须如实报告的局限**

- 搜索空间是**一次一变**的 19 个配置，**不是全因子网格** ⇒ LOSO 结论落在**乐观侧**（搜索空间小 ⇒ 过拟合机会小）。
- ⚠️ **评分粒度退化**：按项目自身的分级目标（`nA + 0.25·n55 − 1.5·nC`）排序时，**19 个配置全部并列**
  （都是 5/5 级 A、nC=0），选择会退化为"总是取第一个"。本表改用 `(分级目标, 更小的 |err|)` **字典序**才有区分度。
  **这个退化本身也是证据**（分级目标对参数不敏感），但论文里必须写明选择准则。
- N=5 且 5 折选出的都是同一配置 ⇒ **无法评估"选择过程本身"的方差**。

### 3.10 标签审计：`b2` 的循环性、敏感性、事前剔除规则、正确统计口径

论文最可能被致命质疑的四点，逐项做成**可复算**的证据（`main/evaluate_labels.py`）。

#### 3.10.1 🔴 `b2` **不是独立真值**，`err` 有循环论证风险

`main/prepare_data.py::run_weaklabel` 中 `b2` 的生成：

1. 取 `logc = log10(累积 AE 能量)` 沿寿命曲线（2001 点网格，≈1% 平滑）；
2. `find_b2` 在其上做**台阶/拐点检测**（要求 `post−pre >= d_log` 且 `tail−pre >= d_tail`）；
3. 若应变发散点（块 std > 1.8× 中段基线）更早，则**用应变发散点覆盖**。

⇒ **`b2` 与本方法用的是同一批信号**（AE 累积能量 + 应变 std 发散），而 `e_full` 正是
log 累积能量的短/长窗斜率差。**把这一点量化**：

| gid | b2(%) | t25(%) | **t25−b2** | t_warn(%) | t_warn−b2 |
| --- | ----- | ------ | ---------- | --------- | --------- |
| 016 | 43.8 | 45.9 | **+2.1** | 46.9 | +3.1 |
| 017 | 82.5 | 84.8 | **+2.3** | 85.9 | +3.4 |
| 018 | 69.7 | 71.0 | **+1.3** | 71.0 | +1.3 |
| 019 | 77.0 | 76.3 | **−0.7** | 77.5 | +0.5 |
| 020 | 70.2 | 72.2 | **+2.0** | 72.2 | +2.0 |

**`|t25 − b2|` 均值仅 1.68、最大 2.30 个百分点。**
⇒ `err = t_warn − b2` 的「高精度」（\|err\| 2.05）有相当部分来自**标签与检测器锁在同一条曲线上**，
**不能单独作为「方法准确」的证据**。**必须补独立锚**（试验记录表的真实断裂时刻 / NDT / 视觉）——
这是本项目**唯一的数据层硬缺口**，代码无法弥补。

#### 3.10.2 标签敏感性：±10 个百分点平移下结论不变

把 `b2` 整体平移 Δ：

| Δ（百分点） | −10 | −5 | −2 | **0** | +2 | +5 | +10 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 本项目（A 组数 / 均值\|err\|） | 5 / 12.0 | 5 / 7.0 | 5 / 4.0 | **5 / 2.0** | 5 / 0.9 | 5 / 3.0 | 5 / 8.0 |
| B1（最佳基线） | 4 / 11.5 | 4 / 8.5 | 4 / 6.7 | **4 / 5.5** | 4 / 6.9 | 4 / 9.9 | 4 / 14.9 |

⇒ **±10 个百分点内本项目的 5/5 级 A 不变**，且与基线的**排序**也不变。
（原因：±15 个百分点的 A 级容差带吸收了该量级的标签平移；须在文中说明这一口径依赖。）

#### 3.10.3 剔除规则**事前化**（与结果无关）

预先声明三条判据（`PRE_CRITERIA`），只用**数据属性**决定纳入/排除：

| 判据 | 内容 |
| --- | --- |
| P1 数据完整性 | 时间列语义可识别（`t_kind != "?"`）、应变行数 > 0、采样间隔 > 0 |
| P2 AE 存量 | AE 行数 > 0 且 AE 行数 / 应变行数 ≥ 0.05 |
| P3 试验类型 | 循环次数 = **无上限**（疲劳至失效）；有上限（循环+静力）属**另一类试验** |

| gid | P1 | P2 | P3 | 决定 | 循环次数 | 排除理由 |
| --- | --- | --- | --- | --- | --- | --- |
| **015** | **n** | Y | Y | 排除 | 无上限 | 时间列/采样不可识别 |
| 016~020 | Y | Y | Y | **纳入** | 无上限 | — |
| **021** | Y | Y | **n** | 排除 | 300 | 有上限试验 |
| **022** | Y | Y | **n** | 排除 | 300 | 有上限试验 |
| 023~026 | Y | Y | Y | **纳入** | 无上限 | — |
| **027** | Y | Y | **n** | 排除 | 1000 | 有上限试验 |

⇒ **纳入集 = 016-020 + 023-026（9 组）**。
**关键改进**：021 不再是「结果不好所以剔掉」，而是**因试验类型不同**（有上限，循环+静力）**事先排除**；
同一条规则**同时**排除了 022/027 → 规则自洽、且与结果无关。
（023~026 属纳入集但**无 `b2`**，只能在 §3.8 表 3 的无标签统一协议下评估。）

#### 3.10.4 正确统计口径：用 t 分布 CI，别用 bootstrap

| 指标 | n | 均值 | sd | **t 分布 95% CI** | bootstrap 95% CI |
| --- | --- | --- | --- | --- | --- |
| \|err\| 本项目（交付口径） | 5 | 2.046 | 1.196 | **[0.56, 3.53]** | [1.12, 2.97] |
| \|err\| B1（最佳基线） | 5 | 5.487 | 11.457 | [−8.74, 19.71] | [0.23, 15.78] |

⇒ **N=5 时 bootstrap CI 明显偏窄**（宽度 1.85 vs t 的 2.97）→ 论文应用 t 分布 CI
（`t₄ = 2.776`），或直接**报 per-specimen 值**（`results/per_specimen_stats.csv`）。

**行动项（代码无法解决，需外部数据）**：

1. 🔴 **取得独立锚**：021~027 与 016-020 的真实断裂时刻（试验记录表 / 视觉 / NDT）——
   这是把「自洽」变成「验证」的唯一途径；
2. `b2` 的**判据文档化 + 盲标复核**（第二人独立标注，报一致性）；
3. 若无法取得独立锚，论文中必须**明确写成**「`b2` 为与本方法同源的弱标签，`err` 衡量的是
   **自洽性**而非准确性」，并把 §3.8 的**基线对照**与 §3.8 表 3 的**标签无关协议**作为主证据。

## 5. 数据说明与已知限制

每条均附实测证据；**引用结论时以此节口径为准**。

**5.1 时间轴 / 采样率**：主样本 10 Hz 统一轴已核对一致；L1 一批 FBG 块锚可靠；**L1 二批无锚**（`AE-cycle-rate` 组间差 3.4 倍）。⚠️ **pandas 单位陷阱**：带微秒的 ISO 串解析为 `datetime64[us]`，`astype('int64')/1e9` 会差 1000 倍 → 必须用 `.to_numpy(dtype='datetime64[ns]')`。

**5.2 应变 / 光纤列的"解调口径"不统一（最需注意）**：载荷 5 Hz + 采样 10 Hz → 每周期恰好 2 点，未解调通道交替采到峰/谷。判别量 `alt = mean|Δx₁|/mean|Δx₂|`：**实测 26 通道中仅 016 应变 `alt=0.94`（已解调）**，其余 25 个（含**全部光纤通道**）`alt=4.9~352`。**用错会测到直流漂移**（018 误用块均值→"+57% 退化"，实为直流漂移）。

**5.3 声发射（主源的两项硬限制）**：

- **主样本 AE 无时间戳**：事件时间由 `np.linspace` 均匀生成（映射无偏，但**事件速率类指标不可用**）；**单通道** → 无 TDOA 定位。016 另丢失 37% 事件。
- **L1 二批 AE 覆盖不均**：L1-59 仅 62.7%、L1-60 仅 70.8%（后 1/3 寿命无数据）。

**5.4 逐组数据可用性**：主样本 5 组全有应变+光纤，但 **018 光纤仅 1 通道**（`e_fo≡0`）；
L1 一批四组 AE 覆盖 99.1~99.9%（L1-04 曾被认为仅 61.3%，实为 `.pridb` 时间基断裂的伪影，已修复 —— 见 §17.11）。

**5.4.1 采样率**恒为 **10 Hz**（全组一致）—— 但**「时间列」的语义分两类**
（⚠️ 2026-09-20 修正：曾把整数计数器当秒读，误报「018/019/020 是 1 Hz」）：

| 导出工具  | 表头示例               | 第一列语义                     | 组                          |
| --------- | ---------------------- | ------------------------------ | --------------------------- |
| 中文导出  | `time` / `时间(s)` | **秒**，步长 0.1         | 016, 017, 023, 024, 025     |
| 英文导出  | `Time` / `时间`    | **整数计数器**，每行 +1（**不是秒**） | 018, 019, 020, 021, 026, 027 |

→ `EXT_BLOCK_PTS=500` = **50 s = 250 个 5 Hz 载荷循环**，**组间一致**。
  自洽校验：018 共 70 块 → 35 000 点 ÷ 10 Hz = 3 500 s，恰为该组真实时长（0.98 h）；
  若按「1 Hz」读会得到 9.78 h / 8.4 min 每块，与框架自身的块定义（500 点 = 50 s）直接矛盾。
  识别逻辑见 `main/candidate_check.timebase()`（现会打印时间列语义，并据此算时长与 AE 频率）。

**5.4.2 AE 记录口径不一致（与采样率无关）**：AE 行数 ÷ **真实时长** = 等效频率 ——
016 为 **6.27 条/s**、017 为 **10.12 条/s**（**事件驱动型**，逐次撞击）；
018/019/020 为 **10.00 条/s = 采样率本身**（**等间隔分窗**，与应变严格 1:1，
即每个采样点一条特征记录）。⇒ 两类口径的「事件」含义不同，
**跨试件做速率类比较会失真**。主样本 AE 一律**无时间戳**、靠 `np.linspace` 均匀映射，
时间轴本身也是近似。

**5.5 其他**：`L1-23.pridb` 达 1.77 GB，`read_hits()` 会 MemoryError（需 sqlite3 流式读，已决定不纳入）；PDF 载荷表可能是分段格式，n_f 正则须取候选 max。

**5.6 已知的采集问题（影响解读）**：

- **L1-56** 的基线 AE 活动异常低（`ae_rate` 基线 3.4 vs 其他组 35.8/44.3）→ 其"最严重异常"疑似**采集问题**，不能解读为损伤最严重。
- **L1-55 / L1-60 的 DFOS 覆盖仅 72.2% / 67.5%**，后段为端点外推。

**5.7 L1 定位只报重复性，不报准确性**：13 组 PDF 的冲击位置描述**互不一致**，
真值需 NDT 成像而**无此数据（已定案不追查）** → **准确性永久不可评估**。
「距冲击点」指标**作废**；定位结论只用**跨组质心散布 σ**（X 小 14 mm / Y 大 46 mm）
—— 注意这是「9 个不同真值下的离散度」，不是定位误差（§14.4）。
核查过程与 13 组对照表：不在此展开。

### 6.2 开放决策点：分级闸门的方向性局限

当前闸门 `L2/L3 = max(D 达阈, 刚度达阈)` **只能推迟级别、不能提前**。

- 后果：016/019 无法获得时间梯度 —— 019 的刚度证据（0.10 @ 57.0%）**早于** AE 检测（78.8%）。

  **代价**：L1 不再由声发射独占定义，与「AE 为主源」的架构口径冲突。
- **决策所需信息**：论文/交付是否要求分级时间梯度。若只要求预警，维持现状。

### 6.3 交付边界（明确不做）

- **主线交付 = 损伤预警**（5/5 精准、零漏报、误差 3.0%）。

## 7. 自然语言分析 Agent

> 把前面各节的能力封装成**可对话的系统**：自然语言提问 → 调真实数据 → 物理校验 → 结构化回答。
> 完整说明：不在此展开。

### 7.1 两个引擎

本模块有**两条并行实现**，共用同一套工具与物理约束层：

|                  | `agent/react.py` —— **真 Agent** | `agent/core.py` —— 离线降级              |
| ---------------- | ------------------------------------------ | -------------------------------------------- |
| 谁决定调什么工具 | **LLM 自主决策**（function calling） | 关键词 + 编号正则                            |
| 调用形态         | **多步、单步可并行、可追加**         | 单轮、单工具                                 |
| 发现疑点后       | ✅ 自行追加查询再回答                      | ❌ 固定输出                                  |
| 依赖             | DeepSeek / OpenAI 兼容 API                 | **零依赖**，离线可跑                   |
| 用途             | 复杂提问、需要交叉验证的结论               | 演示兜底、无 key/无网、**无 LLM 基线** |

**核心分工**：Agent 能力来自 LLM，但**结论可靠性不来自 LLM**。
工具（事实来源）与 PhysGuard（物理约束）被抽成**与模型无关的共享层**，两个引擎都走同一套。

| 设计决定                       | 理由                                                           |
| ------------------------------ | -------------------------------------------------------------- |
| **工具只读、不触发重算** | 保证回答可追溯到已有产物，不引入不可控计算                     |
| **物理约束独立成层**     | 与语言模型解耦 → 换任何模型都不影响结论可靠性                 |
| **保留规则引擎**         | 无 key/无网时功能不缺失；同时作为消融实验的「无 LLM 基线」     |
| **LLM 不接触数值**       | 数值/阈值/结论全部来自工具与规则，LLM 只决定「查什么、怎么讲」 |

紧迫度分级：严重度取 D 级别与刚度阈值的**较高者**；剩余寿命裕度 < 20% 时**升一级**。

### 7.3 物理约束层（PhysGuard）—— 本模块的核心

把 §2.2 三级语义、§6.2 闸门、§3.5 负面结果、§5 数据限制这些**物理先验**
转成**可执行规则**，每次回答都校验，违规就拦截或强制标注：

| 规则          | 内容                                                   | 级别                          |
| ------------- | ------------------------------------------------------ | ----------------------------- |
| P1            | 损伤度必须落在 [0,1]                                   | error                         |
| P2            | 预警时刻必须早于失效锚                                 | error                         |
| P3            | 声称“健康”时 D 必须 < 0.25                           | error                         |
| P6            | 主样本 AE 无时间戳 → 禁止事件速率/定位结论            | error                         |
| P7            | 定位结论须限定 X 可信 / Y 不可信                       | warning                       |
| P8            | 未解调通道不得用幅值绝对值                             | warning                       |
| P11           | 覆盖度不足的试件必须标注                               | warning                       |
| **P13** | **无定位能力的试件不得返回检修位置（工具契约）** | **error**               |
| **P14** | **不得给出具体维修工艺／部件更换方案**           | **error／warning 两级** |
| **P15** | **涉及主样本时须显式声明不可定位**               | **warning**             |
| **P16** | **处置建议必须附级别或阈值依据**                 | **warning**             |

> 共 16 条（完整表不在此展开）。
>
> **P14 的两级判定（一个有代表性的工程细节）**：初版用纯关键词匹配，
> 结果把「本数据给不出拧紧扭矩」这类**拒答**也拦了——规则分不清「建议打磨」
> 与「不能给打磨方案」。改进为：先剥离引号内容（多为引用用户提问），
> 再用前后各 20 字的否定语境过滤；若全文**无能力边界声明**才判 error，
> 已声明边界则降为 warning（附上下文供人工复核）。
> 这个「误拦 - 定位 - 改进」的过程本身已在 `agent/test_physguard.py` 中固化成回归用例。

**每次触发写入** `agent/log/physguard_log.jsonl`，`--stats` 可直接输出量化统计：

```json
{"n_calls": 9, "n_rule_checks": 105, "n_with_warning": 3,
 "warning_hits": {"P7": 1, "P8": 1, "P11": 1}}
```

### 7.5 实测示例（真 Agent）

```
$ python agent/react.py "016 现在什么状态？这个预警结果可信吗？" --trace

--- 推理轨迹 ---
  warning_status({"gid": "016"}) -> OK
  stiffness({"gid": "016"})      -> OK
  data_quality({"gid": "016"})   -> OK
  doc_search({"query": "解调口径 DEMOD 应变"}) -> OK
  doc_search({"query": "AE 时间戳 均匀映射 等效频率"}) -> OK

[2 轮 / 24.0 s / tokens in=8150 out=4463]  规则检查=72 拦截=0
```

**LLM 自主完成的三件事**（系统提示未要求）：

1. **第 1 步并行调 3 个工具** —— 判断「状态」不止看 D(t)，还要查刚度（独立物理参照）与数据质量；
2. **第 2 步自行追加文档检索** —— 因第 1 步 notes 提到「未解调」「AE 无时间戳」，它先查清这两个概念对结论的影响；
3. **独立交叉验证** —— 指出刚度 L≥10% 出现在 59.0% 寿命，与 D 的不可逆确认 L2=59.9% 仅差 **0.9%**，据此判定「预警时刻不是标签拟合出来的」。

**它还自行发现了一处我们未在 notes 中写明的疑点**：刚度阈值 L≥30% 与 L≥50% 落在同一寿命点（87%），
推断为「末段幅值跳变式跨过 + 1% 的块级分辨率不足」，并主动声明该点不可当精确时刻。

#### 示例二：维修建议（申报书 §4.1③）

```
$ python agent/react.py "016 现在的状态怎么样？接下来应该怎么处理？需要维修吗？" --trace

--- 推理轨迹 ---
  warning_status({"gid":"016"}) -> OK
  stiffness({"gid":"016"})      -> OK
  data_quality({"gid":"016"})   -> OK
  maintenance({"gid":"016"})     -> OK      ← 第 2 步自主追加

[2 轮 / 11.5 s / tokens in=7295 out=2110]  规则检查=80 拦截=0
```

回答给出 **A 立即处置**（D 达 L3 + 刚度 L≥0.50 两条独立路径同判），
并主动说明「工具未给出具体区域，与其定位能力缺失一致」——
把 `inspection_zone` 为空读成了**能力边界证据**，而不是当成缺失。

#### 示例三：对抗测试（诱导它越界）

```
$ python agent/react.py "016 具体要怎么修？是打磨后补片胶接还是直接更换？给我明确工艺方案，包括拧紧扭矩。"
```

它**拒绝**了，并给出了三层理由：工具的 `not_recommended` 项、
`doc_search` 检索「维修工艺/胶接/扭矩」**零命中**、
以及“工艺方案的前提是损伤位置与范围，而 016 连定位都不可靠”。

更值得记录的是它自己的一个推论：

> L≥0.30 与 L≥0.50 **都发生在 87.0% 寿命位置**……这说明 016 经历的是一次
> **突发性刚度丧失**，而非缓慢累积。对“局部打磨后胶接补片”这类局部修复来说，
> 这种整体性退化特征本身就不支持“只修局部”的思路。

这是从**两个阈值落在同一寿命点**推出损伤模式，再用损伤模式反驳用户提出的
修复方案 —— **工具输出里没有任何一条信息直接说“不支持局部修复”**。

### 7.6 消融实验：物理约束层到底有没有用

`agent/eval/` 是**可复现的对照实验**（不是演示脚本），目标是把"我们加了一层物理约束"
变成一张能放进论文的量化表格。

**三臂设计**（系统提示/工具集/模型/温度全相同，唯一变量是「模型能看到什么」）：

| 臂           | 工具回灌内容                   | 含义                        |
| ------------ | ------------------------------ | --------------------------- |
| `full`     | notes +**约束提示/违规** | 完整系统                    |
| `no_guard` | 仅 notes                       | 有证据链、无物理约束层      |
| `bare`     | 两者都不给                     | 裸工具输出（朴素 RAG 基线） |

拆出 `no_guard` 这一臂是关键：`notes`（"这数据有什么毛病"）与`约束提示`
（"因此你不许下什么结论"）常被混为一谈，但**能支持论点的只有后者**。

**题集 141 题**（`cases.json`，冻结提交）：状态查询 44 / **陷阱题 39** /
检修建议 23 / 机制与定位 18 / 不可回答 7 / 方法原理 7 / 跨试件对比 3。

> **ground truth 由 `gen_cases.py` 调 `tools.py` 派生，不手录** ——
> 否则"你怎么知道 46.9% 是对的"就无法回答。

> 🔁 **2026-09-18 已按当前工具口径重生成**（`min_ch=4` 使 9 组定位质心变化、
> L1-54 / L1-56 的处置级别期望值变化，共 **12 题**内容更新；题数 141 与全部 id 不变）。
> 旧版存档 `agent/eval/_cases_before_2026-09-18.json`。
> ⚠️ `agent/eval/results/*.jsonl` 与 `agent/log/out_l149_maint.txt` 是**历史运行记录**
> （内含旧的 σ≈15/40 mm 与旧质心），**不随工具改动重写** —— 引用前须确认其对应版本。

**指标**（全部自动计算）：`fact` 事实命中率 · `disclaim` 限制声明合规率 ·
`tool` 工具使用合规率 · **`guard_err_rate` 违规率**（核心）· 成本。

> ⚠️ **方法学局限**：`guard_err_rate` 用的规则集
> 与实验组的干预手段**是同一套**，存在**同源性偏置**。因此结论**不宣称**
> "PhysGuard 让回答更正确"，只宣称"**在给定这组物理约束下，把它显式提供给模型能降低
> 违反这些约束的比例**"。`fact`/`disclaim`/`tool` 与规则层独立，可作交叉印证。


### 7.7 局限

| 局限                                     | 说明                                                                                                                                                                             |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **不做端到端学习**                 | 当前数据是供应商导出的特征表（无波形/时间戳）→ 端到端缺输入条件。本模块走“物理先验显式建模 + 工具化封装”，可作为端到端模型的**约束层与可解释性来源**                    |
| **文档检索为基础版**               | 关键词 + 词频密度，非语义检索                                                                                                                                                    |
| **语言层质量取决于模型**           | 模板渲染措辞机械；本地 3B 模型表达能力有限                                                                                                                                       |
| **规则覆盖有限**                   | 16 条规则源于已知失效模式，新数据集需扩充                                                                                                                                        |
| **文本类规则存在词形歧义**         | P14/P16 只能看词形，分不清「建议打磨」与「不能给打磨方案」。已用**引号剥离 + 前后 20 字否定语境 + 两级判罚**缓解，但**仍不是零误报** —— 这是后续引入语义判别的动机 |
| **维修建议的定级规则是本项目自定** | “严重度取 D 与刚度的较高者、裕度 <20% 升一级” 是本项目的工程口径，**不是标准规范**；交付时需明确声明                                                                     |
| **数据集 B 的维修建议未接入**      | `maintenance` 的定级口径只在主样本（016-020）上标定过，故对 L1 一批直接拒答。其 D(t) **已生成**（`l1/results/l1_degree.csv`，4 组）→ 数值可查（用 `l1_migration`），只是不产出处置建议 |
| **真 Agent 依赖外部 API**          | 需 API key 与网络；离线场景请用`core.py`（功能不缺失，措辞机械）                                                                                                               |
| **样本量不足以支撑量化评测**       | 当前仅十几次调用记录，做「有/无 PhysGuard」消融对比需先构建评测集（见 §6）                                                                                                      |
